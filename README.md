# Rust Bindings for the Sylvan library

This crate provides unsafe Rust bindings for the parallel multi-terminal binary decision diagram library [Sylvan](https://github.com/trolando/sylvan), currently based on version `1.11.0`, and its work-stealing framework [Lace](https://github.com/trolando/lace). The crate compiles on Linux and macOS. The minimum supported Rust version is `1.85`.

Sylvan and Lace are included as git submodules in `3rd-party` and are compiled directly using the `cc` crate. Building requires a C compiler and `libclang` (used by `bindgen`). When building from a git checkout, run `git submodule update --init` first.

The bindings are generated by `bindgen` and use the same names as the C API. Sylvan defines many operations as macros (e.g. `sylvan_and(a, b)` expands to `RUN(sylvan_and, a, b, 0)`); these are ported to Rust functions with the same names and arguments by `tools/generate_macros.py`. For documentation, see the original source code and the [tutorial](https://trolando.github.io/sylvan/).

All Sylvan operations must be executed inside a Lace worker. The crate provides `lace_run_callback` to run a callback inside a worker:

```rust
use std::ffi::c_void;
use sylvan_sys::*;

unsafe extern "C" fn run(_context: *mut c_void) {
    unsafe {
        // Check that the basic identity (a & b) <=> !(!a | !b) holds.
        let a = sylvan_ithvar(1);
        let b = sylvan_ithvar(2);

        let a_and_b = sylvan_and(a, b);
        let not_a_or_b = sylvan_not(sylvan_or(sylvan_not(a), sylvan_not(b)));

        // The BDD has three nodes:
        assert_eq!(3, sylvan_nodecount(a_and_b));
        // And the identity holds:
        assert_eq!(a_and_b, not_a_or_b);
    }
}

fn main() {
    unsafe {
        lace_start(0, 0); // auto-detect thread count

        // 2MB memory limit should be enough for a small test:
        sylvan_set_limits(1 << 21, 1, 5);
        sylvan_init_package();
        sylvan_init_bdd();

        lace_run_callback(Some(run), std::ptr::null_mut());

        sylvan_quit();
        lace_stop();
    }
}
```

A slightly more involved example is also available in the `test.rs` module.

## Upgrading from 1.x

Version `2.0.0` replaces the hand-written wrapper with generated bindings, which breaks the API:

 - Functions use the C names, e.g. `Sylvan_and` is now `sylvan_and` and `Lace_start` is now `lace_start`. Constants such as `MTBDD_TRUE` are now `mtbdd_true`.
 - Sylvan operations must be executed inside a Lace worker, see `lace_run_callback`.
 - `Lace_suspend` and `Lace_resume` were removed from Lace; idle workers now sleep automatically.
 - The `build_sylvan` feature was removed, since the sources are bundled with the crate.
